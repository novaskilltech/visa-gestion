# EXTENSION DU CAHIER DES CHARGES
## Visa Gestion — SaaS B2B pour agences de voyages

---

# 106. POSITIONNEMENT COMMERCIAL

Visa Gestion devient une plateforme SaaS B2B destinée principalement aux :

- agences de voyages ;
- agences Omra / Hajj ;
- tour-opérateurs ;
- professionnels du voyage sollicitant une société spécialisée dans le traitement des visas.

La proposition de valeur est :

> **Centralisez vos demandes de visas, transmettez les documents de vos voyageurs et récupérez les visas terminés depuis une interface professionnelle et sécurisée.**

Visa Gestion doit permettre de remplacer :

- WhatsApp ;
- emails dispersés ;
- dossiers Google Drive ;
- échanges manuels de fichiers ;
- tableaux Excel de suivi.

---

# 107. MODÈLE B2B

Une agence cliente dispose de son propre espace.

Exemple :

```text
Visa Gestion
│
├── Agence Atlas Voyages
│   ├── Utilisateur 1
│   ├── Utilisateur 2
│   └── Dossiers visas
│
├── Agence Salam Travel
│   ├── Utilisateur 1
│   └── Dossiers visas
│
└── Agence Horizon Travel
    ├── Utilisateur 1
    ├── Utilisateur 2
    └── Dossiers visas
```

Chaque agence doit être totalement isolée des autres.

Une agence ne doit jamais pouvoir :

- voir les voyageurs d'une autre agence ;
- accéder aux documents d'une autre agence ;
- connaître ses volumes ;
- rechercher ses dossiers ;
- accéder à ses visas.

# 110. NOUVEAUX RÔLES

La structure des rôles devient :

```text
SUPER_ADMIN
VISA_AGENT
AGENCY_ADMIN
AGENCY_USER
```

## SUPER_ADMIN

Gestionnaire de Visa Gestion.

Il peut :

- voir toutes les agences ;
- créer ou désactiver une agence ;
- gérer les utilisateurs ;
- voir tous les dossiers ;
- affecter les dossiers ;
- consulter l'activité générale ;
- accéder aux paramètres SaaS.

## VISA_AGENT

Personne chargée du traitement des visas.

Elle peut :

- voir les dossiers qui lui sont affectés ;
- consulter les documents ;
- demander une pièce ;
- traiter le dossier ;
- uploader le visa final.

## AGENCY_ADMIN

Responsable d'une agence cliente.

Il peut :

- créer des dossiers ;
- uploader des documents ;
- voir tous les dossiers de son agence ;
- récupérer les visas ;
- gérer les utilisateurs de son agence si cette fonction est activée.

## AGENCY_USER

Collaborateur d'une agence.

Il peut :

- créer des dossiers ;
- uploader des documents ;
- suivre les dossiers autorisés ;
- récupérer les visas autorisés.

---

# 112. SÉCURITÉ MULTI-TENANT

Les règles RLS doivent vérifier l'appartenance réelle de l'utilisateur à l'organisation.

Un utilisateur d'une agence peut consulter uniquement :

```text
visa_cases.organization_id
=
organization_members.organization_id
```

et uniquement si :

```text
organization_members.user_id = auth.uid()
```

La simple présence d'un utilisateur authentifié n'est jamais suffisante.

# 138. PRINCIPE MULTI-TENANT

La notion d'organisation doit être présente dès la première migration de base de données.

Ne pas développer d'abord une application mono-agence puis ajouter les organisations ultérieurement.

Cela entraînerait :

- migrations complexes ;
- réécriture des RLS ;
- risques de fuite inter-clients ;
- refonte des utilisateurs ;
- refonte des dossiers.

---

# 139. PRODUIT FINAL

Visa Gestion doit désormais réunir deux produits cohérents :

```text
SITE PUBLIC B2B
+
APPLICATION MÉTIER PRIVÉE
```

Le visiteur voit un SaaS professionnel.

L'agence connectée voit un outil opérationnel.

Le gestionnaire voit un backoffice complet.

Les trois expériences doivent partager :

- même marque ;
- même design system ;
- même qualité de finition ;
- même niveau de confiance.

---

# 140. NOUVELLE DÉFINITION DU PRODUIT

**Visa Gestion est une plateforme B2B permettant aux agences de voyages de transmettre, centraliser et suivre les dossiers de visas confiés à une société spécialisée, depuis la réception des documents jusqu'à la mise à disposition du visa final.**

La plateforme automatise également l'extraction et le contrôle initial des informations présentes dans les documents afin de réduire les ressaisies et les erreurs.
